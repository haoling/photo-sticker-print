# 写真の割り付けと印刷

写真をシールのコマに割り付けて、印刷用の PDF / PNG を作る。写真は、Immich の写真リストから選ぶ（[Immich 連携](immich.md)）か、手元のファイルを画面からアップロードする。どちらもサーバーには保存しない。

## 使い方

1. 画面の「写真を割り付け」タブで、**用紙**を選ぶ。
2. **写真を選ぶ**。写真リスト（Immich）から選ぶか、「手元のファイルを選ぶ」（空いているコマに順に入る）。写真リストで何も選んでいないときにコマを押すと、そのコマに手元のファイルを選べる。「1 枚目の写真で全部埋める」もある。
3. **塗り足し**を決める（既定 1mm）。
4. **最終確認の画像を作る**。サーバーが作った画像（赤: コマの輪郭、青の点線: 塗り足しの範囲）と、警告が出る。
5. 確認できたら **PDF をダウンロード**（予備で PNG）。設定や写真を変えると確認画像が古くなり、PDF / PNG は押せなくなる（用紙を無駄にしないため）。
6. PDF を、用紙サイズ **はがき**・拡大縮小 **100%（実際のサイズ）** で印刷する。給紙位置・用紙の種類・フチありは、画面の「推奨設定」に合わせる。

位置補正は、[テスト印刷](test-print.md)の画面で決めた用紙ごとの値が自動で使われる。

## 塗り足し

ハーフカットの位置と印刷位置は、どうしても少しずれる。写真をコマぴったりに刷ると、ずれた側に白い隙間が出るので、コマの外側へ写真をはみ出させる。

- 写真は、塗り足しを含めた範囲（コマを四方へ広げた角丸四角形。角丸の半径も塗り足しの分だけ大きくする）いっぱいに、**中央を基準に切り抜いて**敷く。コマに見える部分はその中央なので、塗り足しの分だけ周りが少し多めに切り落とされる。
- はみ出した部分は台紙に刷られるだけで、シールには残らない。
- 範囲は 0〜3mm。既定は 1mm（要件の初期値）。
- **なぜ 1mm か**: コマ位置は写真から測った推定値（29622 は X 方向 ±0.3mm・Y 方向はノギスで確認済み、29662 は ±0.3〜0.5mm、26009 は ±0.2mm）で、これにプリンタの用紙送りの誤差とハーフカットの公差が重なる。1mm あればそれらを吸収できる。コマの隙間（29622 は横 12mm・縦 4.5mm、26009 は 3mm）にも収まり、隣のコマに干渉しない。
- 0.8mm 未満にすると警告が出る。

## 警告

次のとき、最終確認の画面に警告が出る。

- 塗り足しが 0.8mm 未満（コマ位置の誤差や用紙送りの誤差で、白い隙間が出やすい）。
- 塗り足しが、フチあり印刷で印刷できない範囲にかかる（TS7630 のはがきでは用紙の端から約 5mm。上下の 3mm / 5mm のどちらが上かが未確認なので、安全側に 5mm を両方に使っている）。端が白く抜ける可能性がある。
- 塗り足しが用紙の外にはみ出す（はみ出した分は切り落とされる）。

| 2026-11-16 | 29622 | Canon TS7630 | はがき、写真用紙 光沢スタンダード、きれい、後トレイ、100%、位置補正なし | 0.5mm | 仕上がりは良好。ただし印刷がハーフカットより **下に約 0.6mm・右に約 0.2mm** ずれて出て、剥がしたシール 2 枚（コマ 1 とコマ 10）とも**上端に約 0.1〜0.15mm の白い線**が出た。左右と下端には出ていない |
| 2026-11-16 | 26009 | Canon TS7630 | 赤枠のテスト印刷と同じシート（そのほかの設定は未記録） | 1mm | 仕上がりは良好。剥がした跡の台紙に、印刷の帯が**四辺とも（上辺も）**残っていて、塗り足し 1mm が全辺で効いている。帯は下が最も厚く、印刷はハーフカットより下に寄っている。赤枠（別の印刷）に対して、写真は右・下へ 0.2〜0.3mm 程度寄っていた（概算） |
| 2026-11-16 | 26009 | Canon TS7630 | **IPP で直接送信**。はがき、普通紙、後トレイ、フチあり、きれい | 1mm | **10 コマすべてで、写真が赤枠（前に刷ったテスト印刷。ハーフカットとほぼ同じ位置）の外まで回った**。確認用の画像と、印刷結果の切り抜きが一致。剥がした 1 枚は、四辺とも写真で覆われていた。白い隙間は見当たらない（目視） |

- 29622: 台紙に残った印刷の帯は、下が約 1.0〜1.2mm、上がほぼなし、左が約 0.4〜0.5mm、右が約 0.8〜0.95mm だった（塗り足し 0.5mm のとき、ずれがなければ四辺とも 0.5mm）。
- 29622 のコマ 1 とコマ 10 は同じシートを 1 回給紙した結果なので、独立した 2 つの証拠ではない。**この 1 回のずれが、毎回出る系統的なものか、印刷のたびにばらつく誤差か**は、まだ区別できない。
- 29622 のずれの原因は用紙送りと見られる。コマ位置は、上端・下端の余白をノギスで測って両方 7.5mm と確認した（定義の上端 7.5mm・ピッチ 27.5mm と一致）ので、定義の誤差ではない。
- 観察が 3 つ並んだ。**ずれの向きも量も、印刷のたびに変わっている**。

  | 観察 | ずれ |
  | --- | --- |
  | 26009 の赤枠のテスト印刷 | 右に 0.1〜0.3mm 程度（目視） |
  | 26009 の写真の印刷（塗り足し 1mm） | 下に寄っている。赤枠の印刷に対して、右・下へ 0.2〜0.3mm 程度（概算） |
  | 29622 の写真の印刷 | 下に約 0.6mm、右に約 0.2mm |

  26009 の赤枠のテスト印刷と写真の印刷は、**同じシートを別々に給紙した 2 回の印刷**で、その間にも 0.2〜0.3mm のずれがあった。同じ用紙・同じ設定でも、印刷のたびに位置が変わっていることになる。

  「用紙の種類で決まる系統的なずれ」より、「印刷のたびにばらつく用紙送りの誤差」に近いように見える（家庭用プリンタなら自然）。ただし 3 回だけなので、断定はできない。
- **結論: 塗り足しは 1mm 程度にする。** ずれがばらつく誤差なら、補正値では直せず、塗り足しで吸収するしかない。1mm なら、今回のずれ（約 0.6mm）を補正しなくても吸収でき、残りの 0.4mm でばらつきを受けられる。
- 用紙ごとの位置補正（テスト印刷の画面）は、ずれが毎回同じ向き・同じ量で出るとわかった場合にだけ意味がある。既定は 0 のままにする。

### 用紙送りのばらつきを測る（任意）

塗り足し 1mm で足りるかは、ずれがどれだけばらつくかで決まる。26009 は 12 枚あるので、同じ設定で枠線のテスト印刷を何回か刷って、ハーフカットとの位置の差を測れば、ばらつきがわかる。

- 同じ PDF（位置補正 0）を、同じ設定で 5 回ほど刷る（毎回シートを入れ直す）。
- 1 枚ずつ、台紙ごと真上から撮る（コマの輪郭が見える明るさで）。写真から、用紙ごとの位置のずれを測れる。
- ばらつきが大きければ、毎回の誤差で、塗り足しを決める材料になる。小さくて平均が 0 からずれているなら、補正値で直せる。

## 29622 に刷るとき

29622 は 5 枚しかないので、刷る前に次を確認する。

- 塗り足しは **1mm**。
- 最終確認の画像で、写真の切り抜きと向きを確かめ、**警告がない**ことを確かめる。
- 印刷の設定: はがき、100%、後トレイ。用紙の種類は光沢系（上の結果は「写真用紙 光沢スタンダード」・「きれい」）。**シールの印刷面を上にするか下にするかは、用紙のパッケージの指示に従う。**
- 29622 は上下・左右とも余白がほぼ対称なので、シートを逆向きに入れても位置はほとんど変わらない。
- 1 枚のシートの使っていないコマは、そのまま次の印刷に使える（空のコマには何も刷られない）。

**未確認のこと**

- 29662（光沢フィルム）で、29622 と同じずれ方をするか。
- 29622 の X 方向のコマ位置（左端 13.0mm・ピッチ 43mm。ノギスでは未確認で、±0.3mm 程度）。Y 方向は確認済み。
- 用紙送りのずれが、毎回同じか、ばらつくか（29622 は 1 枚、26009 は 1 回しか刷っていない）。

## API

`POST /api/sheet/render?format=preview|png|pdf`（multipart/form-data）

| フィールド | 内容 |
| --- | --- |
| `paperId` | 用紙の id（必須） |
| `bleedMm` | 塗り足し（mm、0〜3、既定 1） |
| `offsetX` / `offsetY` | 位置補正（mm、-10〜10、既定 0） |
| `cell-<番号>` | そのコマの写真のファイル（0 始まり。上の段から、左の列から） |
| `photo-<番号>` | そのコマの写真の、フォトストレージ（Immich）での id。画像はサーバーが取る。同じコマに `cell-` と両方は指定できない |
| `edit-<番号>` | そのコマの編集パラメータ（JSON。省略可。下記） |

- `preview` は 150dpi・確認用の輪郭つき。`png` は 600dpi（はがきは 2362×3496）、`pdf` は用紙と同じ大きさの 1 ページ。
- 警告は、レスポンスヘッダ `x-sheet-warnings`（JSON を URL エンコード）で返す。
- フォトストレージに無い写真は 404、フォトストレージ側の問題（つながらない・API キー）は 502。
- 写真が読めないコマは 422、コマ位置が未測定の用紙は 409、入力の誤りは 400、存在しない用紙は 404。
- EXIF の向きを反映する。透過 PNG は白地に載せる。HEIC など sharp が読めない形式は 422（Immich 連携では Immich 側で変換済みのプレビューを使う予定）。

### 編集パラメータ（`edit-<番号>`）

元の写真は変えず、コマごとにパラメータだけを持つ。画面のプレビューとサーバーの印刷画像は、同じ計算（`cropRect`）を使う。

```json
{ "zoom": 2, "focusX": 0.25, "focusY": 0.5, "rotation": 90, "flipH": true }
```

| 項目 | 内容 | 範囲・既定 |
| --- | --- | --- |
| `zoom` | 拡大率。1 = 枠いっぱいに敷く、2 = 2 倍 | 1〜8、既定 1 |
| `focusX` / `focusY` | 切り抜きの中心。回転・反転後の写真の左上が 0、右下が 1 | 0〜1、既定 0.5 |
| `rotation` | 時計回りの回転（EXIF の向きを反映したあと） | 0 / 90 / 180 / 270、既定 0 |
| `flipH` | 左右反転（回転のあと） | 既定 false |

- 範囲外・知らない項目・JSON でない値は 400。写真のないコマの編集も 400。
- 計算は `fixtures/cell-edit-cases.json` のゴールデンケースで、サーバー（`packages/server/src/print/cellEdit.ts`）と画面（`packages/web/src/cellEdit.ts`）の両方が同じ値になることを確かめている。2 つに分けて実装しているのは、サーバーが tsc の出力だけで動く構成を保つため。
- 編集の画面（ズーム・位置・回転）は M3 で作る。今の画面は、いつも既定の編集で送る。
