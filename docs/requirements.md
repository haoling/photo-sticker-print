# 要件

## 1. 目的

手元のフォトストレージ（まずは Immich）にある写真を、ブラウザだけで市販のシール用紙に「ズレずに」「楽に」印刷できるようにする。

## 2. スコープ

### 2.1 最初に対応するもの

| 種別 | 対象 | 備考 |
| --- | --- | --- |
| フォトストレージ | Immich | API キーで接続 |
| 用紙 | エーワン 29662 写真シール高画質 Medium | はがきサイズ（100×148mm）、1片 23×31mm、10面（2列×5段）、光沢フィルム |
| プリンタ | Canon PIXUS TS7630 | 「同じシリーズ」扱いのプリンタも含む（後述） |

### 2.2 やらないこと

- マルチユーザー（ログイン・ユーザーごとの設定・権限管理）
- 写真のアップロードや Immich 側データの変更（読み取り専用）
- プリンタドライバの代替（色管理や用紙送りの細かい制御）

## 3. 構成

- **ブラウザアプリ（フロントエンド）**: 割付・編集・プレビュー・印刷データ生成
- **小さなサーバー（バックエンド）**: Immich API へのプロキシ
  - Immich の API キーはサーバー側の環境変数に置き、ブラウザには渡さない
  - ブラウザ ↔ サーバー間で Immich の API を必要な分だけ中継する
- 配布形態は Docker イメージ（Immich と同じホストで動かす想定）

### 3.1 環境変数

| 変数 | 必須 | 内容 |
| --- | --- | --- |
| `IMMICH_URL` | ○ | Immich サーバーの URL（例: `http://immich-server:2283`） |
| `IMMICH_API_KEY` | ○ | Immich の API キー（読み取り権限のみで足りるようにする） |
| `PORT` | | 待ち受けポート |

### 3.2 セキュリティ

- アプリ自体には認証を持たない（シングルユーザーのため）
- その代わり、このアプリは「Immich の写真を API キーの権限で読めるプロキシ」になるので、**LAN 内限定 or リバースプロキシ側で認証をかける前提**とし、README に明記する
- プロキシは必要なエンドポイントだけを許可リスト方式で中継する（Immich API を素通しにしない）

## 4. 画面

### 4.1 PC（横幅が広い場合）

画面を左右に分割する。

- **片側: 印刷プレビュー（シート）**
  - シール用紙を実寸比で表示し、各コマに写真を表示
  - 写真リストからコマへドラッグ＆ドロップで割り付け
  - コマ同士のドラッグで入れ替え
  - コマをクリックすると、そのコマの編集モードに入る（後述）
  - 「同じ写真で全部埋める」「選んだ写真を順に流し込む」などの一括操作
- **もう片側: 切り替えパネル**
  - 写真リスト（Immich）
  - コマの編集
  - 設定

### 4.2 スマホ

左右分割はしない。1画面で以下を切り替える。

- メインはシートのプレビュー（縦長の用紙が画面にほぼ収まる）
- 空のコマをタップ → 写真リストが全画面（またはボトムシート）で開き、選んだらそのコマに入る
- 写真入りのコマをタップ → 編集画面が全画面で開く
- 設定はメニューから
- ドラッグ＆ドロップの代わりに「タップで選択 → 入れ替え先をタップ」で並べ替えできるようにする

## 5. 機能要件

### 5.1 写真リスト（Immich）

- タイムライン（新しい順）でサムネイル一覧、無限スクロール
- アルバム一覧 → アルバム内の写真
- 検索（Immich のスマートサーチ／人物）は後回しでよいが、入れられる構造にする
- 複数選択してまとめてシートに流し込み
- 動画は除外（あるいは選択不可表示）

### 5.2 コマの編集

- 切り抜き（コマの縦横比に固定したトリミング枠、ピンチ／ホイールでズーム、ドラッグで位置調整）
- 回転（90°単位 + 微調整の自由回転）
- 左右反転
- フレーム（白フチ、角丸、色付き枠、柄など。フレームはデータとして追加できるようにする）
- 編集のリセット
- 編集内容は元画像を変更せず、パラメータ（トリミング位置・倍率・角度・フレーム ID）として保持する

### 5.3 印刷

- 用紙の実寸（mm）に基づいて印刷データを生成する
- **塗り足し**: コマの外側に少し（初期値 1mm 程度、設定可能）画像をはみ出させ、ハーフカットとのズレで白い隙間が出ないようにする
- **位置補正（キャリブレーション）**: プリンタごとの印刷ズレを X/Y の mm 単位で補正できる
  - 普通紙に枠線だけを印刷する「テスト印刷」を用意し、シール用紙と重ねて透かしてズレを測れるようにする
- 印刷方法
  1. ブラウザの印刷ダイアログ（CSS `@page` で用紙サイズ指定）
  2. PDF ダウンロード（ブラウザ印刷で拡大縮小・余白が入ってしまう環境向けの確実な手段）
  3. （将来）サーバーから IPP でプリンタへ直接送信
- 印刷前に、プリンタ側で選ぶべき設定（用紙サイズ、用紙の種類、フチあり／なし、給紙位置、拡大縮小 100%）を用紙定義から案内表示する
- 解像度: 300dpi 以上相当で出力（23×31mm なら約 272×366px 以上）。画像は Immich のプレビュー画像を基本とし、足りない場合はオリジナルを使う
- EXIF の回転情報を正しく扱う。HEIC などブラウザで扱えない形式は Immich 側で変換済みのプレビューを使う

### 5.4 用紙

- 用紙は設定画面で選び、ブラウザに保存する（Cookie または localStorage）
- 用紙は **データ（JSON 等）として定義**し、コード変更なしで追加できるようにする
  - 用紙サイズ（mm）
  - 各コマの位置・サイズ（mm）、角丸半径
  - 推奨プリンタ設定（用紙種類、フチあり／なし など）
  - 必要なプリンタ能力（対応用紙サイズ、フチなし要否）
  - メーカーの製品ページ URL、型番、JAN
- コマ位置はメーカー提供のテンプレートや実測から起こし、実物で検証したものに「検証済み」マークを付ける

### 5.5 プリンタ

- プリンタは「機種」ではなく **能力の組み合わせ（プリンタプロファイル）** で扱う
  - 対応用紙サイズ
  - フチなし印刷の可否（用紙サイズごと）
  - 印刷プロトコル（OS ドライバ経由、AirPrint/IPP など）
- 能力が同じ機種は同じシリーズとしてまとめ、まとめて「**たぶん対応プリンタ**」と言い切る
- 用紙が要求する能力をプロファイルが満たしているかを判定し、満たさない組み合わせは警告する
- プリンタも設定画面で選び、ブラウザに保存する。位置補正値はプリンタ × 用紙ごとに保存する

### 5.6 設定・状態の保存

- ブラウザ側に保存するもの: 選択中の用紙、プリンタ、位置補正値、塗り足し量、作業中のシート（割付と編集パラメータ）
- 作業中のシートはリロードしても消えない
- サーバー側に保存するもの: なし（環境変数のみ）

### 5.7 フォトストレージの抽象化

- Immich 以外（他のセルフホスト系フォトストレージ、クラウドフォトサービス等）を足せるよう、フォトストレージを以下のインターフェースで抽象化する
  - 写真一覧（ページング）、アルバム一覧、アルバム内の写真
  - サムネイル取得、印刷用画像取得
  - 写真のメタデータ（縦横サイズ、向き、撮影日時）
- 有効にするストレージは環境変数で切り替える

## 6. 非機能要件

- 対応ブラウザ: PC は最新の Chrome / Edge / Firefox / Safari、スマホは iOS Safari / Android Chrome
- 印刷データの生成はブラウザ側で行い、サーバーは軽量に保つ
- 画像はシートに置いた分だけ取得し、サムネイルはキャッシュする
- UI は日本語（将来の多言語化を妨げない作り）

## 7. 未決事項

- フロントエンド / バックエンドの技術スタック（M0 で決める）
- 29662 の正確なコマ位置（メーカーテンプレートと実物で確認）
- 29662 をフチあり印刷で問題なく刷れるか（コマが印刷可能領域に収まるか）
- TS7630 で IPP 直接印刷がどこまで使えるか（AirPrint / Mopria 対応なので IPP 自体は使える見込み）
- 用紙設定の保存先を Cookie と localStorage のどちらにするか（サーバーで読む必要がなければ localStorage が素直）
