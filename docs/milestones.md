- [x] 実機調査の結果から、印刷データの変換方式（コンテナ内 CUPS か、自前生成 + IPP 直接送信か）を決める

  - [tech-stack.md](tech-stack.md) に記録。画像生成は sharp、PDF は pdf-lib、IPP は自前実装の方向（M1 で最終確認）
- [x] リポジトリの雛形、Lint / Format / テスト、CI
- [x] Dockerfile と docker compose の例（host ネットワーク版と通常ネットワーク版）

- [x] シートのプレビュー表示（実寸比）

- [x] 印刷ジョブの状態表示（待機中・印刷中・完了、用紙切れ・インク切れなどの理由）
- [x] 26009 に写真を IPP で刷って、10 コマすべてで白い隙間が出ないことを確かめる（26009 の用紙定義を `verified` に）: 2026-11-16 確認、`verified` にした
- [x] PDF ダウンロード（予備）と、PDF から印刷するときの設定案内
- [x] 位置補正（X/Y mm）とテスト印刷（枠線のみ）のデータ生成（PNG / PDF / SVG、線の色の指定、テスト印刷の画面。[使い方](test-print.md)）

  - [ ] 補正値の保存（プリンタ × 用紙ごと。M4）

**完了条件**（達成: 2026-11-16）: TS7630 に IPP で **26009** の写真を印刷し、10 コマすべてで白い隙間が出ない。26009 の用紙定義に「検証済み」が付く。

> 29662（3 枚入り）・29622（5 枚入り）は高価なので、開発のテストには使わない。26009（12 枚入り・安価）で足りる。29662 の実機検証は、開発がすべて終わったあと（M7）に行い、位置が違っていたら「29662 の用紙定義を正しくする」を別のタスクにする。
