# Immich 連携

Immich の写真を、写真リスト（タイムライン / アルバム）から選んでコマに入れる。Immich へは読み取りだけで、写真やアルバムは変えない。

> 2026-11-17 に、実際の Immich で確認した（Immich から選んだ写真だけで 1 シートを作り、操作に違和感なし）。テストは、Immich の API（`@immich/sdk` 3.4.1 の型定義）に合わせたモックで行っている。

## 準備（API キー）

Immich の「アカウント設定 → API キー」でキーを作り、サーバーの環境変数 `IMMICH_URL` / `IMMICH_API_KEY` に設定する。必要な権限は次の 4 つだけ。

| 権限             | 使いみち                                             |
| ---------------- | ---------------------------------------------------- |
| `asset.read`     | 写真の一覧（検索）                                   |
| `asset.view`     | サムネイル・プレビュー画像                           |
| `asset.download` | 元のファイル（プレビューの解像度が足りないときだけ） |
| `album.read`     | アルバムの一覧                                       |

## 使い方

1. 「写真を割り付け」タブの写真リストで、**タイムライン**（新しい順）か**アルバム**を開く。写真は撮影日ごとに見出し（例: 2026年1月5日（月））でまとまり、見出しはスクロールしても上に残る。下までスクロールすると続きが読まれる。動画は出ない。
2. コマに入れる。方法は 2 つ。
   - **写真を押す**: 空いているコマ（番号の若い順）に、すぐ入る。入っている写真には ✓ が付く（同じ写真を複数のコマに入れると ✓2 のように数が出る）。空いたコマがないときは、押しても入らない。
   - **コマへドラッグ＆ドロップ**: 落としたコマに入る（入っていた写真と入れ替わる）。
3. あとは手元のファイルのときと同じ（[写真の割り付けと印刷](sheet-print.md)）。手元のファイルと混ぜてもよい。

## API キーをブラウザに出さない仕組み

- API キーと Immich の URL は、サーバーの中だけで使う。ブラウザが呼ぶのは、このアプリの次の入口だけ（許可リスト方式。Immich の API をそのまま通す入口はない）。

  | このアプリの入口                 | サーバーが呼ぶ Immich の API                 |
  | -------------------------------- | -------------------------------------------- |
  | `GET /api/photos?cursor=&limit=` | `POST /api/search/metadata`（写真だけ・新しい順） |
  | `GET /api/albums`                | `GET /api/albums`                            |
  | `GET /api/albums/:id/photos`     | `POST /api/search/metadata`（`albumIds`）    |
  | `GET /api/photos/:id/thumbnail`  | `GET /api/assets/:id/thumbnail?size=thumbnail` |
  | `GET /api/photos/:id/preview`    | `GET /api/assets/:id/thumbnail?size=preview` |
  | （印刷データを作るときだけ）     | `GET /api/assets/:id/original`               |

- 写真・アルバムの id は UUID の形だけを受け付ける（パスを書き換える値は 400）。
- Immich のエラーの本文はブラウザに渡さず、理由を言い換えて返す（API キーが違う・権限が足りない・つながらない）。
- 画像の応答は、種類が画像のものだけを渡す。Immich からのリダイレクトには従わない。
- テスト（`packages/server/src/photoRoutes.test.ts`）で、どの応答にも API キーと Immich の URL が出てこないことを確かめている。

このアプリ自体には認証がない。**アプリを開ける人は、API キーの権限で読める写真をすべて見られる**ので、LAN 内だけで使うか、リバースプロキシで認証をかけること。

## 印刷に使う画像

- シートを作るとき、ブラウザは写真の id だけを送る（`photo-<コマ番号>`）。画像はサーバーが Immich から取る。
- 基本は **プレビュー画像**（Immich の既定で長辺 1440px の JPEG。向きを反映済みで、HEIC なども変換済み）。
- 敷く範囲（塗り足しを含む）での解像度が **300dpi に足りないときだけ、元のファイル**を取り、読めて、より細かければそちらを使う。
  - 26009（40×24mm）や 29622 / 29662（23×31mm）では、拡大しなければプレビューで足りる（26009 で約 870dpi）。足りなくなるのは、大きく拡大したとき（M3 の編集）。
  - 元のファイルが読めない形式（HEIC・RAW など）のときは、プレビューのまま刷り、最終確認に「解像度が低め」の警告を出す。
- 最終確認と印刷で同じ写真を続けて使うので、取った画像はサーバーのメモリにしばらく持つ（200MB まで。ディスクには保存しない）。

## フォトストレージを足すとき

`packages/server/src/photos/storage.ts` の `PhotoStorage`（写真の一覧・アルバムの一覧・アルバム内の写真・写真の情報・サムネイル・プレビュー・元のファイル）を実装して、`buildApp` の `storage` に渡す。写真の id とページの続き（cursor）は、ストレージごとの不透明な文字列として扱っている。環境変数での切り替えは、2 つ目のストレージを足すときに入れる。

## 開発用のモック

実機の Immich がなくても、色つきの写真を入れたモックで画面を確かめられる。

```bash
pnpm --filter @photo-sticker-print/server exec tsx src/testing/demoImmich.ts
```

表示された `IMMICH_URL` / `IMMICH_API_KEY` を付けて `pnpm dev` を起動する。
